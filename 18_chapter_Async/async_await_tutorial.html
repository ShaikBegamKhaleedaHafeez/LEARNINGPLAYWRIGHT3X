1. Why do we need async code?

JavaScript is single-threaded — it runs one piece of code at a time. But real-world apps do slow things: network calls, database queries, reading files, timers. If the browser waited for each one to finish, the whole page would freeze.

Asynchronous code lets JavaScript start a slow task, keep running other code, and come back to handle the result later — without blocking the page.

Think of a restaurant:

  • Synchronous = the waiter stands at the kitchen until your pizza is ready. Nobody else gets served.
  • Asynchronous = the waiter takes your order, serves other tables, and the kitchen calls out "Pizza ready!" when it's done.

Three eras of handling that "call me back later" behaviour:

OldCallbacksCallback hell 😵
ModernPromisesChained, flat-ish 👍

2. Callbacks — the old way

A callback is simply a function passed into another function, to be called later. 

function fetchData(callback) {
  // Simulate a slow network request
  setTimeout(() => {
    callback("User data received");
  }, 1000);
}

fetchData(message => {
  console.log(message);
});
User data received
Callback hell: when callbacks are nested inside callbacks, the code starts growing to the right — hard to read, hard to debug: 
openBrowser(() => {
  goToLogin(() => {
    enterCredentials(() => {
      clickLogin(() => {
        console.log("Logged in!"); // 🥴 deep nesting
      });
    });
  });
});

3. The Promise object — new Promise()

A Promise is an object that represents a value that isn't available yet, but will be — either successfully or with an error. It has three states:

  • pending — work in progress (initial state)
  • fulfilled — success, result is available
  • rejected — failed, an error/reason is available

The constructor takes a function with two parameters, resolve and reject:

let order = new Promise((resolve, reject) => {
  let foodReady = true;
  if (foodReady) {
    resolve("Pizza is delivered!");  // -> .then()
  } else {
    reject("Order Cancelled");      // -> .catch()
  }
});
Rule of thumb: call resolve(value) on success, reject(error) on failure. Only one of them wins — the first call decides the state.

4. .then(), .catch(), .finally()

Consume a promise with three chained methods:

MethodRuns when…Gets
.then()fulfilledthe resolved value
.catch()rejectedthe error reason
.finally()always (either way)nothing — cleanup only
apiCall
  .then(response => console.log(response))   // success path
  .catch(error => console.log(error))        // failure path
  .finally(() => console.log("Done anyhow!")); // always runs
User data Done anyhow!
💡 Test-automation analogy: finally() is like a teardown step — close the browser or clear test data whether the test passed or failed.

5. Promise chaining

Each .then() returns a new promise, so you can chain steps — and each step receives the previous step's returned value. Perfect for sequential flows like a login journey: 

function openBrowser() {
  return new Promise(resolve => resolve("Browser is opened!"));
}
function goToLogin() {
  return new Promise(resolve => resolve("Login Page is opened"));
}

openBrowser()
  .then(msg => { console.log("Step 1", msg); return goToLogin(); })
  .then(msg => console.log("Step 2", msg))
  .catch(err => console.log("Error:", err))
  .finally(() => console.log("Execution is done"));
Step 1 Browser is opened! Step 2 Login Page is opened Execution is done
Key point: you must return the next promise inside .then() to keep the chain alive. One .catch() at the end catches errors from any step.

6. async / await — the modern way

async marks a function as asynchronous (it always returns a Promise). await pauses the function until a promise settles, then gives you the value directly. The same login flow becomes nearly synchronous-looking: 

async function loginFlow() {
  try {
    const step1 = await openBrowser();     // pauses here
    const step2 = await goToLogin();
    console.log(step1, "→", step2);
  } catch (err) {
    console.log("Error:", err);   // like .catch()
  } finally {
    console.log("Execution is done"); // like .finally()
  }
}
loginFlow();
Browser is opened! → Login Page is opened Execution is done
Best practice: always wrap await in try / catch / finally — an unhandled rejected promise inside an async function becomes an uncaught error.
🚦 await only works inside async functions (or top-level modules). And note: await pauses that function only — the rest of the program keeps running.

7. Promise.all — run in parallel, wait for all

When tasks are independent, don't run them one after another — launch them all at once and wait for every one to finish. Promise.all takes an array of promises: 

const checkAuth   = Promise.resolve("Auth OK");
const checkDB     = Promise.resolve("DB OK");
const checkCache  = Promise.resolve("Cache OK");

Promise.all([checkAuth, checkDB, checkCache])
  .then(results => console.log("All checks", results))
  .catch(error => console.log("error:", error));
All checks [ 'Auth OK', 'DB OK', 'Cache OK' ]
Promise.allBehaviour
All fulfill→ array of results, in the same order as the input
One rejects→ immediately rejects with that error ("fail fast"); other results are ignored
const checkDB = Promise.reject("DB Down");
Promise.all([checkAuth, checkDB, checkCache])
  .then(results => console.log("All checks", results))
  .catch(error => console.log("error:", error));
error: DB Down
💡 Test-automation analogy: run multiple independent API health checks in parallel — but if one is down, the whole suite fails fast.

8. Promise.race — first to settle wins

Promise.race also takes an array, but settles as soon as the first promise settles (fulfilled or rejected) — it doesn't wait for the rest. 

let fastServer = new Promise(resolve => {
  setTimeout(() => resolve("Fast 100ms"), 100);
});
let slowServer = new Promise(resolve => {
  setTimeout(() => resolve("Slow 500ms"), 500);
});

Promise.race([fastServer, slowServer])
  .then(winner => console.log("Winner:", winner));
Winner: Fast 100ms
💡 Real-world use: timeouts — race a real request against a timer that rejects, so a hanging API call can't freeze your app: 
const timeout = new Promise((_, reject) =>
  setTimeout(() => reject(new Error("Request timed out")), 5000)
);
Promise.race([fetch(url), timeout]);

9. Promise.allSettled — wait for everyone, succeed or fail

Unlike all, allSettled never short-circuits. It waits for every promise to settle and reports each one's outcome — perfect when you want results even if some fail (e.g., running a test suite where failures are expected and reported, not fatal): 

Promise.allSettled([
  Promise.resolve("Test A Passed"),
  Promise.reject("Test B Failed"),
  Promise.resolve("Test C Passed")
]).then(results => {
  results.forEach((r, i) => {
    console.log("Test", (i + 1) + ":", r.status, "-", r.value || r.reason);
  });
});
Test 1 : fulfilled - Test A Passed Test 2 : rejected - Test B Failed Test 3 : fulfilled - Test C Passed

Mental model:
  1. Callback = "call me when you're done."
  2. Promise = a ticket that says "I'll be fulfilled or rejected later."
  3. async/await = sugar on top of promises, so code reads top-to-bottom.
  4. all / race / allSettled = combine multiple promises: wait for all, first, or everyone.
